# Авторская глава 8: сигнальные ворота, уровни 241–260

`authored-layouts.json` — фиксированные координаты стрелок и ворот, а также ожидаемый граф каждого поля. `build_chapter.py` собирает из него отдельный `MazeArrows/Data/levels-v2.json` и проверяемый `content-manifest.json`. В приложении нет случайной генерации этой главы. Старые генераторы и `levels.json` не используются для построения новых полей.

Имена KA/KB соответствуют ключам ○/◇. Имена P/Q/X/Y/C/U/V/T/Z сохраняют смысл из дизайн-документа главы. Цифровой суффикс обозначает обычное короткое продолжение соответствующей ветви. Например, `X1` — дополнительная стрелка области X; её точный предшественник указан в `deps`, а не выводится из имени. Производственные ID имеют префикс номера: `s241_KA`, `s241_ga1`.

- `nodes`: клетки от хвоста к голове, затем направление головы.
- `deps`: **все** обычные стрелки на полном прямом луче перед головой; список проверяется на точное совпадение, включая дальние блокеры.
- `gatepaths`: **все** клетки ворот на полном луче; отсутствие записи означает отсутствие ворот.
- `gates`: `[точный_ID_ключа_в_макете, x, y]`. У группы один ключ, у ключа может быть несколько ворот.
- `titleRU` / `titleEN`: названия для редактора и описания содержания. В производственном JSON `name` содержит английское название; текущий интерфейс кампании показывает номер уровня.

## Проверка и пересборка

Из корня репозитория:

```sh
python3 MazeArrows/Tools/GatesChapter/build_chapter.py
```

Это проверка без записи. Она также требует точного совпадения с зафиксированным JSON. После осознанной правки макета:

```sh
python3 MazeArrows/Tools/GatesChapter/build_chapter.py --write
```

Команда записывает только `levels-v2.json` и `content-manifest.json`. SHA-256 старых 240 уровней обязан совпадать с `f781f36eb3a64e8e2e84c5fb3e693e83e0f1425cc37a801d63acd7a06fb223c9`; при расхождении сборка прекращается. Не обновлять этот эталон ради прохождения проверки.

Необязательный контактный лист требует Pillow; сама сборка использует только стандартную библиотеку Python:

```sh
python3 MazeArrows/Tools/GatesChapter/build_chapter.py --contact-sheet Research/2026-10-16-game-development/08-v2-chapter-contact-sheet.png
```

Это инженерный чертёж с внутренними ID и обозначениями A/B, не скриншот игры и не маркетинговый материал. В игре используются ○/◇.

## Что доказано автоматической проверкой

1. Геометрия: непрерывность и уникальность клеток тела, совпадение последнего сегмента с направлением, отсутствие пересечений, корректные размеры и ссылки ворот.
2. Точный граф: дополнительная стрелка не может случайно перекрыть дальний выход и разрушить независимость ветвей. Декларативные `deps`/`gatepaths` сверяются с реальными координатами.
3. Ацикличность и полное прохождение. Проверяются **все достижимые состояния удалённых стрелок**, а не одно удачное решение. Каждый разрешённый ход сохраняет доступность остальных разрешённых ходов и не приводит к тупику.
4. Значимость каждой отдельной клетки ворот: находится достижимое состояние, где ключ ещё на поле, стрелка запрещена, а удаление только этих ворот разрешило бы её. Свидетельство записано в `gateWitnesses`. Это обнаруживает декоративные ворота, дубли одной группы на одном луче и ворота, эффект которых уже заменён телом ключа.
5. №241 начинает только с KA. В №251 и №258 одни ворота лежат на двух перпендикулярных лучах; встречных взаимно блокирующих стрелок нет.

На первом зафиксированном наборе: **20 уровней, 234 стрелки, 42 клетки ворот; 1 724 достижимых состояния и 4 378 разрешённых переходов**. Swift-тесты `V2ChapterContentTests` дополнительно сверяют этот независимый граф с настоящим `MoveValidator` на всех достижимых состояниях, защищают смысловые узлы и проверяют независимые порядки подготовки двойных барьеров.

## Осознанная корректировка относительно бумажных брифов

Числа стрелок в брифах были ориентиром, а не обязательным минимумом. Геометрии содержат **6–16 стрелок**, финал — 15. Мы сохранили все двадцать смысловых узлов, но отказались от наполнения поля до 30 стрелок только ради числа. Обычные продолжения короткие и связаны с конкретными участками. Это особенно важно после последних открытий: длинная уборка уже пустого поля не должна заменять задачу.

№256 имеет два почти зеркальных крыла с доступными ключами. №257 добавляет заметную обычную подготовку только одного ключа. №258 соединяет общий перекрёсток, последовательность ключей и обычное схождение. №259 разделяет левый/правый выходы с одним условием и центральный выход с двумя. №260 использует две подготовки первого ключа, две пары ворот, центральную обычную стрелку и финальное схождение. Эти четыре поля не сводятся к удлинению обучающей очереди №241.

Техническая проверка не заменяет плейтест. Предположения о темпе и удобстве чтения поля требуют игры на устройстве; проверок на реальных игроках в этом наборе не заявлено. Перед релизом использовать критерии из документов `06-chapter-08-gates-design.md` и `07-chapter-08-level-briefs.md`. После публикации эти ID и координаты также становятся историческим контентом: дальнейшие главы добавлять отдельно.

Запись для описания обновления и результаты интеграционных проверок ведутся в корневом **VERSION_2.md**.
